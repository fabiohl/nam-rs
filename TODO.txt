## 🟠 Dívidas Técnicas e Observações para Sprints Futuras

### Gestão de Lifetimes do PipeWire (prioridade: média)
- O uso de `std::mem::forget(stream)` e `std::mem::forget(_listener)` em audio.rs
  impede a destruição prematura dos proxies PW, mas é um "leak intencional".
- Recomenda-se migrar para uma struct `AppState` que ancore Stream + Listener,
  mantendo ownership explícita e permitindo shutdown limpo.
- Pode ser abordado ao integrar o motor de inferência (Sprints 2-3).

### Parametrizações Futuras — Gain Staging (Tarefa 4.2)
- O payload `ParamPayload::LoadModelPtr(*mut ())` é um placeholder opaco.
  Na Tarefa 4.1, deve ser substituído por um container tipado que aponte para
  as estruturas SoA decodificadas do .namb sem alocação dinâmica.
- O campo `input_level_dbu` do cabeçalho .namb DEVE ser interpretado e aplicado
  ao reescalonador pré-convolucional. Omissão deste limiar desalinha a curva
  não-linear (tanh) e gera distorção digital destrutiva.

### Preparativos para Sprint 2 & std::simd
- Nenhuma dependência de std::simd foi adicionada ainda. A feature gate
  #![feature(portable_simd)] será necessária, ou usar diretamente
  core::arch::x86_64 para intrinsics.
- O Cargo.toml está enxuto (5 deps). Dependências matemáticas futuras
  (multiversion para multiversioning SIMD) devem ser adicionadas via
  `cargo add` conforme o planejamento da Sprint 2.
- O `process()` pass-through será substituído pelo callback de dados nativo
  que invoca o motor de inferência WaveNet/LSTM.
- Qualquer injeção do "Loop do Modelo NAM" dentro do callback `process()`
  deverá manter-se 100% estática via Const Generics para não incorrer no
  custo letal para o Branch Target Buffer (BTB).

### select_optimal_cpu() — Robustez (prioridade: baixa)
- A seleção de CPU por capacidade + IRQs é funcional, mas opera com
  Vec<> na inicialização (fora da thread RT, sem impacto).
- Em ambientes sem `/sys/devices/system/cpu/cpuN/cpu_capacity`
  (containers, VMs), o fallback para 1024 é razoável.

### Testes de Integração PipeWire (prioridade: média)
- O teste de unidade SPSC em buffer.rs valida concorrência lock-free.
- Falta um teste de integração que verifique a injeção nula (pass-through)
  no PipeWire real, conforme critério da Tarefa 1.3. Isso requer um daemon
  PipeWire ativo e pode ser implementado como teste condicional (#[cfg(test)])
  ou como teste de CI com PipeWire em modo headless.
