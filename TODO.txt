Obs Para a Tarefa 1.2 (Estabilização Lock-Free — src/buffer.rs):
buffer.rs está praticamente vazio. Contém apenas SHUTDOWN: AtomicBool. Toda a infraestrutura SPSC (ring buffers, payloads alinhados #[repr(align(128))], AlignedBlock) foi removida intencionalmente.
rtrb foi removido do Cargo.toml. Se a Tarefa 1.2 decidir reusar rtrb para a comunicação CLI → DSP, será necessário readicioná-lo via cargo add rtrb.
Novo design de payload necessário. O antigo RingPayload era orientado a gravação (Audio, Metadata, StreamStop). O novo payload deve ser orientado a parametrização: input gain, output gain, troca de modelo .namb, metadados Tone3000. Projetar com #[repr(align(128))] para blindagem de False Sharing.
OVERRUN_COUNT foi removido. Se o novo SPSC precisar de contagem de overruns, criar um novo AtomicU64 com semântica adequada.

Obs Para a Tarefa 1.3 (Construção do Host PipeWire — src/audio.rs):
O plugin agora se chama NamRsPlugin com const NAME = "NAM-rs". Não mais AudioRipPlugin.
process() é pass-through. O corpo do callback está vazio (exceto a configuração RT na primeira chamada). A Tarefa 1.3 deve inserir a lógica de recepção de parâmetros via SPSC (do lado consumidor) e, futuramente, a cadeia de processamento: Input Gain → Resampler → NAM Inference → Output Gain → Resampler.
nih_plug ainda é o framework de host. Se a Tarefa 1.3 decidir migrar para pipewire-rs nativo (sem o nih_plug), a refatoração será significativa: descartar toda a trait Plugin, substituir por um MainLoop + Context + callbacks nativos.
O campo metadata_sent foi removido. A Tarefa 1.3 precisará de seus próprios flags de estado (ex: model_loaded, resampler_ready).
reset() é no-op. Quando o motor de inferência tiver estados recorrentes (LSTM hidden states), o reset() precisará zerar esses buffers.
