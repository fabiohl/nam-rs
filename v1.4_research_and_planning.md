## 1. Análise da Arquitetura A2 (NeuralAmpModelerCore 0.5.2)

### 1.1 O que é A2

A2 é a nova arquitetura "slimmable" do NAM upstream. Diferente da A1 (WaveNet padrão com `tanh` fixo + gated `tanh×sigmoid`), a A2 introduz:

| Componente                 | A1 (NAM-rs atual)                | A2 (NeuralAmpModelerCore 0.5.2)                                                                                                                                        |
| -------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Ativações**              | `tanh` fixo, `sigmoid` gated     | Enum `ActivationType` com 11 variantes (Tanh, HardTanh, FastTanh, ReLU, LeakyReLU, PReLU, Sigmoid, SiLU/Swish, HardSwish, Softsign, LeakyHardTanh). Per-layer configs. |
| **Gating**                 | Booleano simples (`gated: bool`) | Enum `GatingMode` (NONE, GATED, BLENDED) com `GatingActivation` e `BlendingActivation` classes                                                                         |
| **FiLM Conditioning**      | ❌ Não existe                    | `FiLM` class — Feature-wise Linear Modulation via Conv1x1 em 8 pontos de inserção por layer                                                                            |
| **Bottleneck**             | channels = bottleneck            | `bottleneck` separado (channels internas < canais de layer)                                                                                                            |
| **Grouped Convolutions**   | ❌                               | `groups_input`, `groups_input_mixin` para depthwise/grouped Conv1x1                                                                                                    |
| **Head1x1**                | ❌                               | Conv1x1 opcional entre ativação → head (skip connection)                                                                                                               |
| **Layer1x1**               | ❌                               | Conv1x1 opcional entre ativação → residual (next layer)                                                                                                                |
| **Post-Stack Head**        | head_scale escalar               | `HeadParams` com Conv1D stack multi-camada (kernel_sizes variável)                                                                                                     |
| **Condition DSP**          | ❌                               | DSP embarcado (pode ser outro modelo NAM!) como pré-processador do conditioning                                                                                        |
| **ConvNet**                | ❌ Não portado                   | Modelo alternativo com BatchNorm + ativação + dilation stacks                                                                                                          |
| **Slimmable**              | ❌                               | Mesmo modelo treinado opera com N canais ou N/2 canais (runtime width)                                                                                                 |
| **ConfigParserRegistry**   | Dispatch manual                  | Singleton registry com auto-registration para arquiteturas                                                                                                             |
| **Per-layer kernel_sizes** | kernel fixo por array            | `kernel_sizes` vetor per-layer                                                                                                                                         |
| **Versioning**             | JSON version check básico        | `IVersionSupportChecker` registry com suporte parcial                                                                                                                  |

### 1.3 Estado Atual do NAM-rs vs A1

O NAM-rs **implementa A1 com paridade completa** e otimizações superiores ao C++ original:

- ✅ WaveNet Standard/Lite/Feather/Nano (const generics)
- ✅ WaveNet Dyn (fallback dinâmico)
- ✅ LSTM 1-layer e 2-layer (const generics + temporal interleaving)
- ✅ LSTM Dyn (fallback)
- ✅ Gated activation (tanh × sigmoid)
- ✅ Kernels SIMD fundidos (Conv1D+Mixin, Tanh+Head, Fused GEMV Residual, Gated Activation)
- ✅ BF16, F16C compression, AVX-512 multiversioning
- ✅ NAMB v1/v2 binary format

## 2. Análise do Ecossistema CLAP

### 2.1 Especificação CLAP

CLAP (CLever Audio Plugin) é um formato aberto de plugin de áudio por u-he + Bitwig:

- **Core**: `clap_plugin_t` com callbacks `init`, `activate`, `process`, `deactivate`, `destroy`
- **Process**: `clap_process_t` com `audio_inputs`/`audio_outputs` (buffers float32/float64), `in_events`/`out_events`, `frames_count`
- **Extensions**: Sistema modular (`CLAP_EXT_PARAMS`, `CLAP_EXT_STATE`, `CLAP_EXT_GUI`, etc.)
- **Thread Model**: `[main-thread]`, `[audio-thread]`, `[thread-safe]` — compatível com o modelo RT do NAM-rs

### 2.2 Opções Rust para CLAP

| Crate      | Nível                | Prós                                                | Contras                                     |
| ---------- | -------------------- | --------------------------------------------------- | ------------------------------------------- |
| `clap-sys` | FFI raw              | Controle total, bindings diretos                    | Muito unsafe, boilerplate pesado            |
| `clack`    | Safe wrapper         | Idiomático, host+plugin, low-level safe             | Menos maduro que nih-plug                   |
| `nih-plug` | Framework alto nível | Multi-formato (CLAP+VST3), produtivo, battle-tested | Opinado, traz VST3 junto (que não é escopo) |

### 2.3 Recomendação Estratégica

> **`nih-plug`** é a opção mais pragmática para plugin CLAP de alta qualidade. Apesar de suportar VST3, é possível compilar apenas o target CLAP. O framework abstrai o lifecycle do plugin e garante RT-safety por design.
>
> **Alternativa**: `clack` para controle granular sem overhead de VST3. Melhor se o objetivo for o binding puro CLAP sem framework.
>
> A **decisão final** pode ser diferida. O staging atual foca em tornar o NAM-rs "plugin-ready" via trait `AudioHost` sem depender de crate CLAP nenhum.

  ┌─────────────────────────────────────────┐
  │         Código Atual (v1.3)              │
  │  pw_host.rs ←→ NamModel ←→ loader/      │
