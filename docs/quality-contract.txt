# ── Tolerâncias aplicadas pelo --check ───────────────────────────────────────
#
# O verificador NÃO exige correspondência exata. As seguintes margens são
# aplicadas para evitar falsos positivos por variação de ambiente (OS, kernel,
# alocador, governor de CPU, versão do compilador, etc.):
#
#   Fidelidade (ESR):        viola se novo > baseline × 10.0
#                            (até 1 ordem de grandeza de degradação tolerada)
#
#   Fidelidade (SNR):        viola se novo < baseline − 6.0 dB
#                            (até 6 dB de perda tolerada)
#
#   Fidelidade (MR-STFT):    viola se novo > baseline × 10.0
#                            (até 1 ordem de grandeza de degradação tolerada)
#
#   Performance (latência):  viola se novo > baseline × 1.10
#                            (até 10% de acréscimo tolerado)
#
# Modelos presentes no baseline mas ausentes na execução atual geram um
# aviso informativo (amarelo), não uma violação.
#
# ── Workflow de calibração / recalibração ────────────────────────────────────
#
# 1. Após validar que uma build está limpa e correta (todos os testes passam,
#    ISA parity ok, sem regressões visíveis no dashboard), capture o baseline:
#
#      utils/quality-dashboard.sh --save docs/quality-contract.txt
#
# 2. Em execuções subsequentes (CI, pré-PR, pós-mudança de código estrutural),
#    valide contra o baseline:
#
#      utils/quality-dashboard.sh --check docs/quality-contract.txt
#
# 3. Recalibre o contrato quando:
#    - Houver mudança estrutural no código que altere intencionalmente a
#      precisão numérica (ex.: novo algoritmo de ativação, troca de acumulador).
#    - Houver mudança de ISA-alvo (ex.: x86-64-v2 → x86-64-v3, aarch64).
#    - O dashboard for estendido com novos modelos golden ativos.
#    - Houver upgrade de toolchain (rustc) com mudança semântica relevante.
#
# ⚠ O contrato NÃO deve ser recalibrado para "esconder" uma regressão.
#    Se uma violação for detectada, investigue a causa raiz antes de
#    recalibrar. A primeira execução pós-recalibração deve ser inspecionada
#    visualmente para confirmar que os novos valores são razoáveis.
#
# ── Formato do arquivo ──────────────────────────────────────────────────────
#
# O conteúdo abaixo é a saída textual de utils/quality-dashboard.sh no modo
# "full", salva via --save. As seções são parseadas pelo --check, que extrai
# as tabelas de fidelidade e performance. Linhas acima deste bloco (incluindo
# este cabeçalho) são ignoradas pelo parser. O parser também ignora seções de
